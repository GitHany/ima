### 安装步骤

#### 第一步：克隆代码

```bash
# 把代码"下载"到本地
git clone https://github.com/username/project.git
cd project
```

> **什么是克隆？** 就像从网盘下载文件，但用Git可以记录每次修改。

#### 第二步：安装依赖

```bash
# 安装项目需要的"零件"
npm install
```

#### 第三步：配置环境

```bash
# 复制配置"模板"
cp .env.example .env

# 用记事本打开 .env，填入必要信息
notepad .env  # Windows
vim .env      # Mac/Linux
```

#### 第四步：启动服务

```bash
# 启动开发服务器
npm run dev
```

### 验证安装

```bash
# 运行健康检查
npm run health

# 预期输出：
✓ Node.js version: v20.0.0
✓ Dependencies installed
✓ Environment configured
✓ Database connected
```

**如果看到全是 ✓**：✅ 恭喜你，环境准备好了！

## 📁 目录结构

### 这是什么？

> **通俗解释**：目录结构就是"房间布局图"，告诉你每个房间是干什么的、什么东西放在哪里。

### 主要目录说明

```
project/
├── src/                    # 源代码目录（主要工作区）
│   ├── components/         # 组件（UI零件）
│   ├── services/           # 服务层（业务逻辑）
│   ├── utils/              # 工具函数（常用小功能）
│   └── index.js            # 入口文件（程序从这里开始）
├── tests/                  # 测试目录（质检区）
│   ├── unit/               # 单元测试（测单个零件）
│   └── integration/        # 集成测试（测零件配合）
├── docs/                   # 文档目录（说明书）
├── config/                 # 配置目录（设置文件）
├── scripts/                # 脚本目录（自动化任务）
│   ├── setup.sh            # 初始化脚本
│   ├── build.sh            # 构建脚本
│   └── deploy.sh           # 部署脚本
├── docker/                 # Docker配置
├── .github/                # CI/CD配置
├── package.json            # 项目配置（零件清单）
└── README.md               # 说明文档（欢迎页）
```

### 主要文件说明

**通俗解释**：这些文件有多重要？

| 路径 | 说明 | 重要性 | 改动风险 |
|------|------|--------|----------|
| `src/index.js` | 应用入口 | ⭐⭐⭐ 核心 | 高 |
| `src/config/` | 配置加载 | ⭐⭐⭐ 核心 | 高 |
| `tests/` | 测试用例 | ⭐⭐ 重要 | 中 |
| `scripts/` | 构建/部署脚本 | ⭐⭐ 重要 | 中 |
| `docker/Dockerfile` | 容器配置 | ⭐ 一般 | 低 |
| `.github/workflows/` | CI/CD流水线 | ⭐ 一般 | 低 |

### 代码规范

**为什么要有规范？** 就像作文有格式要求，代码规范让大家的代码风格一致。

| 类型 | 命名规则 | 例子 | 比喻 |
|------|----------|------|------|
| 变量/函数 | camelCase | `userName`, `getUser()` | 山峰起伏 |
| 类名 | PascalCase | `UserService` | 首字母大写 |
| 常量 | UPPER_SNAKE_CASE | `MAX_COUNT` | 全大写 |
| 文件名 | kebab-case | `user-service.js` | 短横线 |

## 🚀 部署指南

### 这是什么？

> **通俗解释**：部署就是"搬家"——把代码从你的电脑放到真正的"房子"（服务器）里，让所有用户都能住进来。

### 部署方式

#### Docker部署（推荐）

```bash
# 构建"集装箱"
docker build -t project:latest .

# 启动"集装箱"
docker run -d -p 8080:8080 project:latest
```

> **什么是Docker？** 就像搬家时的打包盒——把东西打包好，到哪都能原样打开。

#### 传统部署

```bash
# 安装"家具"
npm install --production

# 构建
npm run build

# 用PM2启动
pm2 start dist/index.js --name project
```

### 环境配置

**通俗解释**：不同的"房子"有不同的配置，开发用的是毛坯房，生产用的是精装修。

| 环境 | 变量 | 什么时候用 |
|------|------|------------|
| 开发 | `NODE_ENV=development` | 本地写代码 |
| 测试 | `NODE_ENV=test` | 跑自动化测试 |
| 预发布 | `NODE_ENV=staging` | 上线前验证 |
| 生产 | `NODE_ENV=production` | 真正服务用户 |

### 数据库迁移

> **什么是数据库迁移？** 就像搬家时调整房间格局——要新增或修改数据表结构。

```bash
# 查看待执行的迁移
npm run migrate:status

# 执行迁移（改结构）
npm run migrate:up

# 回滚迁移（撤销改动）
npm run migrate:down

# 创建新迁移
npm run migrate:create --name add-users-table
```

## 🐛 故障排除

### 这是什么？

> **通俗解释**：故障排除就是"维修手册"——空调不制冷、灯泡不亮，先查这里。

### 常见问题

| 问题 | 可能原因 | 解决方法 | 比喻 |
|------|----------|----------|------|
| 安装失败 | Node版本不对 | 升级到推荐版本 | 电压不匹配 |
| 启动失败 | 环境变量缺失 | 检查 .env 文件 | 没插电源 |
| 数据库连不上 | 配置错误或网络 | 检查连接字符串 | 水管断了 |
| 测试失败 | 依赖没装或环境不对 | 重新 npm install | 零件没装好 |
| 构建失败 | 内存不足或语法错误 | 增加内存或查代码 | 材料不够 |
| 部署失败 | 端口占用或权限不足 | 检查端口和权限 | 门锁住了 |

### 调试技巧

```bash
# 查看详细日志
DEBUG=* npm run dev

# 检查依赖树
npm ls

# 清理后重装
npm cache clean --force
rm -rf node_modules
npm install
```

## ⚠️ 避坑指南

### 这是什么？

> **通俗解释**：避坑指南就是"防骗手册"——告诉大家哪些坑常见、怎么绕过去。

### 新手常犯的错误

| 错误 | 后果 | 正确做法 |
|------|------|----------|
| 把密码提交到Git | 信息泄露 | 用环境变量或 .env 文件 |
| 直接在生产环境调试 | 可能导致故障 | 先在测试环境验证 |
| 不看日志就问人 | 浪费时间 | 先自己排查，看日志 |
| 一次性提交太多改动 | Code Review困难 | 分批次提交，每次改一点 |
| 跳过测试就提交 | 代码质量下降 | 先跑测试，通过再提交 |

### 遇到问题怎么办？

```
1. 看错误信息（别慌，仔细读）
2. 查日志（一般在 ./logs 目录）
3. 搜搜索引擎（Stack Overflow很有用）
4. 问AI助手（描述清楚问题）
5. 问同事（带着你的排查结果）
```
