## 📋 命令详解

### 这是什么？

> **通俗解释**：就像说明书里的"按键说明"——告诉你每个按钮是干什么的。

### 命令列表

| 命令 | 通俗理解 | 什么时候用 |
|------|----------|------------|
| `init` | 初始化/创建 | 开始新项目时 |
| `run` | 运行/执行 | 执行任务时 |
| `stop` | 停止 | 要收工时 |
| `status` | 查看状态 | 检查情况时 |
| `config` | 配置 | 调整设置时 |

### 命令详情

#### init - 初始化

**通俗理解**：就像"开新账户"——创建新东西。

```bash
# 基本用法
command-name init my-project

# 使用模板
command-name init my-project --template typescript
```

#### run - 运行

**通俗理解**：就像"按启动键"——让程序跑起来。

```bash
# 运行任务
command-name run build

# 并行运行
command-name run build test --parallel
```

### 这是什么？

> **通俗解释**：就像电视机的"设置菜单"——调整各种参数让工具按你想要的方式工作。

### 配置文件格式


## 💡 使用技巧

### 这是什么？

> **通俗解释**：就像老司机的"驾驶技巧"——告诉你怎么开得更顺、更省油。

### 技巧1：别名设置

**通俗理解**：给长命令起个小名。

```bash
# ~/.bashrc 或 ~/.zshrc
alias cn='command-name'
alias build='command-name run build'
```

### 技巧2：管道集成

**通俗理解**：把多个工具串联起来用。

```bash
cat data.txt | command-name transform | command-name validate
```

### 技巧3：批量处理

**通俗理解**：一次处理很多文件。

```bash
command-name process "src/**/*.js"
command-name process "logs/*.txt"
```

### 技巧4：调试模式

**通俗理解**：遇到问题时打开"诊断模式"。

```bash
# 详细输出
command-name --verbose

# 干运行（不实际执行）
command-name --dry-run
```

## 🐛 故障排除

### 这是什么？

> **通俗解释**：就像电器说明书里的"问题解答"——告诉你空调不制冷、洗衣机不转怎么办。

### 常见问题

| 问题 | 原因 | 解决方法 |
|------|------|----------|
| 命令未找到 | 没安装或路径不对 | 重新安装或检查PATH |
| 权限不足 | 没有管理员权限 | 用sudo或检查权限 |
| 配置不生效 | 配置文件位置错 | 检查文件路径和格式 |
| 参数解析错误 | 参数格式不对 | 看命令帮助 |

## 🤖 AI 使用提示

> **给 AI 的说明**：使用本文档时，请注意以下要点：
> - 生成命令时必须检查 [参数说明](#参数说明)，避免使用已废弃的参数
> - 涉及文件路径时，优先使用相对路径，注意当前工作目录
> - 批量操作前建议先使用 `--dry-run` 测试（如支持）
> - 涉及删除/修改操作时，必须确认有备份或版本控制
> - 注意区分全局参数和子命令参数的位置
> - 涉及管道操作时，注意数据格式兼容性
