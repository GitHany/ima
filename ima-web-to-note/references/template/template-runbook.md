## ↩️ 回滚方案

### 触发条件

以下情况必须立即回滚：
- 错误率 > 1%
- 核心功能不可用
- 收到用户投诉

### 回滚步骤

#### 步骤1：停止当前操作

```bash
# 如果有正在进行的操作，先停止
kubectl rollout pause deployment/service-name
```

#### 步骤2：执行回滚

```bash
# 回滚到上一版本
kubectl rollout undo deployment/service-name

# 或回滚到指定版本
kubectl rollout undo deployment/service-name --to-revision=2
```

#### 步骤3：验证回滚

```bash
# 确认版本已回滚
kubectl rollout history deployment/service-name

# 验证服务正常
curl http://service/health
```

### 回滚检查清单

- [ ] 服务版本已回滚
- [ ] 功能验证通过
- [ ] 监控指标正常
- [ ] 已通知相关方

## ❓ 常见问题

### Q1: 操作过程中遇到 [错误信息] 怎么办？

**A:** 

1. 检查 [前置条件](#前置条件) 是否全部满足
2. 查看日志：`kubectl logs pod-name`
3. 如果无法解决，执行 [回滚方案](#回滚方案)

### Q2: 验证失败但不确定是否要回滚？

**A:** 

- 如果是非核心功能异常 → 记录问题，评估是否回滚
- 如果是核心功能异常 → **立即回滚**
- 如果不确定 → **立即回滚**（先恢复后排查）

### Q3: 操作超时怎么办？

**A:** 

1. 不要重复执行，先检查当前状态
2. 查看是否有进行中的任务
3. 联系基础设施团队协助
