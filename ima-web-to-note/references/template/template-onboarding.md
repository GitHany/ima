# 新人入职指引

> 欢迎加入团队！这份指南将帮助你快速融入并投入工作。

## 📖 阅读指南

### 入职前（拿到Offer后）
1. **第一步**：阅读 [入职准备](#入职准备)，准备所需材料
2. **第二步**：了解 [团队介绍](#团队介绍)，熟悉组织架构
3. **第三步**：浏览 [技术栈概览](#技术栈概览)，提前了解技术环境

### 第一天（入职日）
1. **第一步**：完成 [入职手续](#入职手续)
2. **第二步**：完成 [账号开通](#账号开通)
3. **第三步**：参加 [新人介绍会](#新人介绍会)

### 第一周
1. **第一步**：完成 [开发环境搭建](#开发环境搭建)
2. **第二步**：完成 [第一个任务](#第一个任务)
3. **第三步**：参加 [团队会议](#团队会议)

### 第一个月
1. **第一步**：独立完成 [一个小需求](#第一个需求)
2. **第二步**：完成 [Code Review](#code-review)
3. **第三步**：准备 [转正答辩](#转正答辩)

### AI 使用提示
> ⚠️ **给 AI 的说明**：使用本文档时，请注意以下要点：
> - 指导新人时必须遵循 [学习路径](#学习路径) 的顺序
> - 环境搭建必须参考 [开发环境](#开发环境) 的具体步骤
> - 不要跳过 [检查清单](#检查清单) 中的验证步骤
> - 涉及权限申请时必须遵循 [权限申请](#权限申请) 流程
> - 代码规范必须以 [代码规范](#代码规范) 为准

## 开发环境搭建

### 硬件检查

- [ ] 电脑配置确认（内存≥16G，SSD≥256G）
- [ ] 显示器连接正常
- [ ] 网络连接正常
- [ ] 外设（键盘、鼠标）正常

### 基础软件

```bash
# 1. 安装 Homebrew (macOS)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 2. 安装开发工具
brew install git
brew install node
brew install yarn
brew install docker
brew install kubectl

# 3. 安装 IDE
brew install --cask jetbrains-toolbox
brew install --cask visual-studio-code
```

### 开发工具配置

#### Git 配置

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@company.com"
git config --global core.editor "code --wait"
```

#### SSH 密钥

```bash
# 生成SSH密钥
ssh-keygen -t ed25519 -C "你的邮箱@company.com"

# 添加到GitLab
cat ~/.ssh/id_ed25519.pub
# 复制输出到 GitLab -> Settings -> SSH Keys
```

#### 克隆代码

```bash
# 创建工作目录
mkdir -p ~/workspace/company
cd ~/workspace/company

# 克隆主仓库
git clone git@gitlab.company.com:project/main.git

# 安装依赖
cd main
yarn install
```

### 环境验证

**简要说明：** 这里提供了验证开发环境是否配置正确的检查命令，确保环境没问题再开始开发。

| 检查项 | 命令 | 预期结果 |
|--------|------|----------|
| Node.js | `node --version` | v18.x 或更高 |
| Git | `git --version` | 2.x 或更高 |
| Docker | `docker --version` | 20.x 或更高 |
| 代码克隆 | `ls main` | 显示项目文件 |

## 第一个任务

### 任务目标

完成一个简单的代码修改并提交PR，熟悉开发流程。

### 任务内容

修改项目 README.md，添加你的名字到贡献者列表。

### 操作步骤

1. **创建分支**
   ```bash
   git checkout -b feature/add-contributor-你的名字
   ```

2. **修改代码**
   - 编辑 README.md
   - 在 Contributors 部分添加你的名字

3. **提交代码**
   ```bash
   git add README.md
   git commit -m "docs: add 你的名字 to contributors"
   git push origin feature/add-contributor-你的名字
   ```

4. **创建PR**
   - 在 GitLab 上创建 Merge Request
   - 指派给你的导师
   - 等待 Review 和合并

### 检查清单

- [ ] 分支命名符合规范
- [ ] Commit 信息符合规范
- [ ] PR 描述清晰
- [ ] 导师 Review 通过
- [ ] 代码已合并到主分支

## 代码规范

### 分支命名

```
feature/功能描述    # 新功能
bugfix/问题描述     # Bug修复
hotfix/紧急修复     # 线上紧急修复
docs/文档更新       # 文档更新
refactor/重构描述   # 代码重构
```

### Commit 规范

```
type(scope): subject

body

footer
```

Type: `feat` `fix` `docs` `style` `refactor` `test` `chore`

示例：
```
feat(user): add user login function

- implement JWT token authentication
- add login page UI
- add unit tests

Closes #123
```

### Code Review 规范

- 至少1人Review通过才能合并
- 关注代码质量、性能、安全
- 保持友善和建设性的评论

## 常见问题

### Q1: 环境搭建遇到问题怎么办？

**A:** 
1. 先查看 [开发环境搭建](#开发环境搭建) 中的常见问题
2. 搜索内部Wiki
3. 询问你的导师
4. 在 #help 频道提问

### Q2: 如何申请生产环境权限？

**A:** 
1. 入职满1个月
2. 通过安全培训考试
3. 在OA系统提交申请
4. 等待主管审批

### Q3: 代码Review不通过怎么办？

**A:** 
1. 仔细阅读Review意见
2. 不理解的地方主动沟通
3. 修改后回复每个评论
4. 重新请求Review

### Q4: 如何快速了解业务？

**A:** 
1. 阅读产品文档
2. 体验产品功能
3. 参加产品讲解会
4. 向产品经理请教
