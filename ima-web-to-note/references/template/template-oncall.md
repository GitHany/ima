## 告警速查

### 告警分级

#### 🔴 P0 - 立即处理

**简要说明：** 这里列出了最严重的告警，收到后必须马上处理，否则会影响核心服务。

| 告警名 | 含义 | 自动处理 | 人工操作 |
|--------|------|----------|----------|
| 服务宕机 | 实例无响应 | 无 | 1. 检查实例状态<br>2. 尝试重启<br>3. 切流量 |
| 数据库主库故障 | 主库不可用 | 自动切换 | 1. 确认切换成功<br>2. 检查数据一致性 |
| 核心链路错误率飙升 | 大量请求失败 | 无 | 1. 查看错误类型<br>2. 判断是否为上游问题 |

#### 🟡 P1 - 15 分钟内处理

**简要说明：** 这里列出了中等严重的告警，需要在15分钟内处理，避免影响扩大。

| 告警名 | 含义 | 自动处理 | 人工操作 |
|--------|------|----------|----------|
| 响应时间升高 | P99 > 500ms | 无 | 1. 查看是否有慢查询<br>2. 检查资源使用 |
| 错误率升高 | 错误率 > 1% | 无 | 1. 查看错误日志<br>2. 判断影响范围 |
| 磁盘空间不足 | 磁盘 > 85% | 无 | 1. 清理日志<br>2. 扩容 |

#### 🟢 P2 - 1 小时内处理

**简要说明：** 这里列出了一般性的告警，需要在1小时内处理，通常不会立即影响服务。

| 告警名 | 含义 | 自动处理 | 人工操作 |
|--------|------|----------|----------|
| 单实例重启 | 某个实例重启 | 自动拉起 | 1. 查看重启原因 |
| 非核心功能异常 | 边缘功能报错 | 无 | 1. 记录问题，白天处理 |

## 故障处理流程

### 通用流程

```
1. 收到告警 → 确认告警真实性（排除误报）
2. 评估影响 → 判断影响范围和严重程度
3. 尝试恢复 → 执行应急操作（先恢复后排查）
4. 通知相关方 → 在值班群同步进展
5. 记录事件 → 记录处理过程和时间线
6. 后续跟进 → 创建事故复盘文档（如需要）
```

### 先恢复后排查

> ⚠️ **原则**：线上故障的第一优先级是恢复服务，不是找到根因。

**简要说明：** 这里列出了不同故障场景下的快速恢复方法，以及可能带来的风险。

| 场景 | 快速恢复手段 | 风险 |
|------|-------------|------|
| 某实例异常 | 下线该实例 | 容量减少 |
| 新版本问题 | 回滚到上一版本 | 丢失新版本数据 |
| 数据库慢查询 | 杀掉慢查询 | 可能影响业务 |
| 缓存击穿 | 开启熔断 | 部分请求降级 |

## 应急操作

### 服务重启

#### 重启影响

**简要说明：** 这里说明了各个服务重启会造成什么影响，以及需要注意的事项。

| 服务 | 重启影响 | 重启时间 | 注意事项 |
|------|----------|----------|----------|
| API 网关 | 短暂 502 | 10s | 需逐个实例重启 |
| 业务服务 | 短暂不可用 | 30s | 确保有健康实例 |
| 数据库 | 不可用 | 2min | **禁止随意重启** |

#### 重启命令

```bash
# 查看服务状态
kubectl get pods -n production | grep service-name

# 滚动重启
kubectl rollout restart deployment/service-name -n production

# 查看重启进度
kubectl rollout status deployment/service-name -n production
```

### 流量切换

```bash
# 切流量到备用集群
kubectl apply -f traffic-backup.yaml

# 验证流量切换
watch curl -s http://health-check-endpoint

# 回切流量
kubectl apply -f traffic-primary.yaml
```

### 回滚操作

```bash
# 查看历史版本
kubectl rollout history deployment/service-name -n production

# 回滚到上一版本
kubectl rollout undo deployment/service-name -n production

# 回滚到指定版本
kubectl rollout undo deployment/service-name -n production --to-revision=3
```

## 常见故障

### 故障1：服务响应慢

**现象**：P99 响应时间 > 500ms

**排查步骤**：
1. 查看是否有慢查询：`kubectl logs -f pod-name | grep "slow"`
2. 查看资源使用：`kubectl top pod pod-name`
3. 查看依赖服务是否异常

**解决方案**：
- 如果是慢查询 → 杀掉慢查询，联系 DBA
- 如果是资源不足 → 扩容实例
- 如果是依赖服务 → 联系对应团队

### 故障2：错误率飙升

**现象**：错误率从 < 0.1% 上升到 > 5%

**排查步骤**：
1. 查看错误类型分布
2. 查看最近是否有发布
3. 查看上游服务状态

**解决方案**：
- 如果是发布导致 → 立即回滚
- 如果是上游问题 → 开启降级/熔断
- 如果是资源问题 → 扩容

### 故障3：磁盘空间不足

**现象**：磁盘使用率 > 85%

**排查步骤**：
1. 查看磁盘使用：`df -h`
2. 查看大文件：`du -sh /var/log/*`
3. 查看日志策略

**解决方案**：
```bash
# 清理旧日志
find /var/log -name "*.log" -mtime +7 -delete

# 或压缩旧日志
find /var/log -name "*.log" -mtime +3 -exec gzip {} \;
```
